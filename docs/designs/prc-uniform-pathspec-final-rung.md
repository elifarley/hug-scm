## Problem Statement

The uniform pathspec contract (elifarley/hug-scm#292) has two rungs shipped:
PR-A (v1.11.0.0, listings + flags) and PR-B (v1.12.0.0, sl* family, `us`,
`a`). Three groups remain on pre-contract behavior — the article's support
matrix still carries `not yet` rows for them:

1. The `w-*` working-directory commands (`w`, `w-discard`, `w-purge`,
   `w-zap`, `w-wipe`, the `-all` variants, the wip family, `w-get`).
2. `llu` — no pathspec filtering of outgoing commits.
3. `sh` — no pathspec filtering of commit details (unlike its siblings
   `shc`/`shcp`/`shp`, which PR-A migrated).

Live probes (2026-08-19, scratch repo) show the pre-contract disease on the
destructives, including one dangerous case:

- `hug w purge -xX` → typo'd flag silently treated as a path, exit 0
  ("Nothing to purge … from the specified paths").
- `hug w discard -- --dry-run` → `--dry-run` consumed as a path, NOT honored
  as a flag — the dry-run safety preview silently skipped when changes exist.
- Magic pathspecs (`:(exclude)build/`) flow into raw git calls unvalidated;
  whether the scoping takes effect is unprobed and unpinned.

## What Makes This Cool

A scope that *restricts destruction* is a safety feature: `hug w purge --
':(exclude)build/'` shrinks the blast radius of the most dangerous commands
in the repo. After PR-C, `-- <path>...` means the same thing on every hug
command, and the support matrix has zero `not yet` rows.

## Constraints

- Scope locked (D1): contract + llu/sh only. Parked issues #301–#304 stay
  parked; they merge as separate small PRs.
- Family breadth beyond the #292 umbrella §8 roster (which names only
  `w-discard`/`w-purge`/`w-zap`/`w-get`) was ratified in-session (D2: full
  scoping for the whole working-directory family — the `:pathspec` article's
  `other w-*` row already claims the family). Consequence: the article's
  support matrix and the conformance roster gain rows for every
  newly-included command (`w-wipe`, the `-all` variants, the wip family), so
  the zero-`not yet` success criterion is non-vacuous.
- Same pipeline and shape as PR-B: one PR, one conformance expansion.
- Standing repo rules: hug commands (never raw git for mutations), Makefile
  test targets, `make sanitize` before every commit, worktree per branch.

## Premises (all confirmed)

1. PR-C is the LAST rung — the #292 ladder closes; nothing follows.
2. The PR-B toolchain transfers as-is — `parse_common_flags_with_pathspecs`,
   `validate_pathspecs_or_die`, `drain_pathspecs_after_separator`, plus the
   conformance roster machinery. One helper does NOT transfer:
   `reject_action_flags` stays listing-only; Class 1 AND the wip family are
   actions and keep their `-f`/`--dry-run`/`--stay`/`--no-squash` flags.
3. One-wave batching: whole family + llu/sh in one PR.
4. Scoped destruction is a NARROWING only (intersection-not-union, §3.1):
   a scope must never widen what an unscoped invocation would touch.
5. `-- --dry-run`-as-path is a bug to fix: a post-`--` token that looks like
   a known flag is rejected loudly (exit 2), never treated as a path.

## Approaches Considered

### Approach A: Family template replay (CHOSEN)
Mirror PR-B: per-command migration onto the proven template (eval
parse_common_flags_with_pathspecs → quiet rehydrate → own-loop with loud
`-*` rejection → validate_pathspecs_or_die → scoped summary gate). Zero new
abstractions; every PR-B pitfall already has a comment in the codebase.

### Approach B: Extraction first (REJECTED)
Land #303's refactor first, then migrate onto the shared entry. Rejected by
decision rule: B only pays if the template changes again after PR-C, and
premise 1 says it won't. B would also double the review surface right after
PR-B's six-round marathon, against D1's scope lock. (User asked for the
decision framework explicitly, then chose A.)

### Approach C: Table-driven generator (REJECTED)
XL over-engineering for a family that stops growing after this PR; generated
bash is harder to review than copied bash.

## Recommended Approach

**A — family template replay.** The pattern survived six codex rounds and
two roasts on PR-B; reviewers know it; the conformance roster/sentinel
machinery (which caught PR-B's missed `slc`) polices the hand-copies.
#303 stays parked as the post-ladder cleanup it was filed as.

## Per-class contract (worked examples ratified in session)

**Class 1 — scoped destructives** (`w-discard`, `w-purge`, `w-zap`,
`w-wipe`; the `w` gateway is TBD pending Open Question 3): FULL scoping.
- `hug w purge -- ':(exclude)build/'` — delete untracked everywhere except build/
- `hug w discard -- ':(glob)src/**.py'` — discard only matching files
- `hug w purge -- ':(exlude)x/'` → exit 2, Invalid pathspec, nothing deleted
- `hug w purge -xX` → exit 2, Unknown option
- `hug w zap --dry-run -- src/` — flags before `--`, paths after; dry-run scoped
- Scoped summary suppression: a scoped answer is the answer (same rule as sl*/us)
- Preview/confirm/delete flow through ONE validated pathspec set: what you
  previewed is provably what gets deleted.
- Compat rule (PR-B family-wide, ratified): bare pre-`--` positionals
  remain accepted and are treated as pathspecs (git parity) — `hug w wipe
  file.js` keeps working and means `hug w wipe -- file.js`. The probe-first
  spike pins any per-command exception red-first before migration.

**Class 2a — whole-tree variants** (`w-discard-all`, `w-purge-all`,
`w-zap-all`, `w-wipe-all`):
no scope by definition (documented escape hatch, like `aa`); parsing hygiene
only (loud typos, exit 2).

**Class 2b — wip workflow** (`w-wip`, `w-unwip`, `w-wipdel`): branch
workflow, no paths exist to scope; parsing convergence only (position-
independent custom flags, loud unknown flags). `reject_action_flags` applies
negatively here — these are actions; their `-f`/`--stay`/`--no-squash` stay.

**Class 3 — new features** (fixed scope, all options):
- `hug llu -- src/` — outgoing commits touching src/ (what am I about to
  push for this subtree?); outgoing range fixed, paths appended to the log.
- `hug sh <ref> -- src/a.py` — commit details filtered to the path,
  matching `shc`/`shcp`/`shp`.

**`w-get`**: already partially migrated (pathspec machinery from PR-A);
finish to full contract in this PR.

## Jargon (PR-B shorthand)

- "quiet rehydrate" — after `eval "$(parse_common_flags_with_pathspecs …)"`,
  re-read the exported `HUG_QUIET` into the script's local `quiet` var.
- "scoped summary gate" — suppress the trailing `hug s` summary iff the
  pathspec array is non-empty (NOT iff `--` was seen).
- "roster/sentinel machinery" — conformance-suite loops over per-family
  command arrays with unknown-row sentinels that fail loudly (see the PR-B
  design: docs/superpowers/specs/2026-08-17-uniform-pathspec-contract-pr-b-design.md).

## Open Questions

- `w-discard`'s `-u`/`-s` (unstaged/staged selection) and `w-purge`'s
  `-u`/`-i` (untracked/ignored) combine with pathspec scope how? (Presumed:
  scope intersects the category — but needs probe-first pinning in the plan.)
- Trailing bare `--` on destructives: picker semantics (like `a`) or inert?
  Presumed picker for interactive commands, but each command's existing
  interactive flow decides; plan must pin per command.
- Does `hug w` (gateway) need its own contract surface, or only correct
  pass-through to subcommands?

## Success Criteria

- The `:pathspec` article's support matrix has zero `not yet` rows.
- Conformance suite gains w-*/llu/sh rows (roster + sentinel arms), all
  two-sided (oracle = raw git, not self-derived).
- The three probed diseases are test-pinned red-first: typo'd flag, `--`
  flag-as-path, malformed magic on destructives.
- Full gate green: `make test` + sanitize; PR review pipeline (codex +
  roast) converges with no MAJOR+.
- #292 closes.
