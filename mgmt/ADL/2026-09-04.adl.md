## 01:55 — pinned_diff misplaced-flag guard: placement + post--- escape hatch

**Context**: Implementing elifarley/hug-scm#284: pinned_diff bound a misplaced --null/--no-renames as a pathspec (silent-empty stdout, exit 0 — worst failure class for an action-list builder) or died as raw git usage. Needed a guard design that cannot break the three existing correct call sites.
**Decision**: Three guard classes inside pinned_diff, all via error_usage exit 2, placed AFTER the arg-count guard and BEFORE any positional read (set -u ordering): (1) format slot rejects a -prefixed token EXCEPT the two valid formats — --name-only/--stat are themselves dash-prefixed, so a naive $1==-* check would reject every valid call; (2) resolved_ref slot rejects ANY dash token — no git ref/range can start with '-', so a dash there is always a misplaced flag; (3) pathspec candidates reject dash tokens ONLY up to the first literal '--' element. KEY FINDING answering the open question: parse_pathspecs (hug-cli-flags) splits at the FIRST '--' and consumes the separator, but a SECOND '--' flows through as a literal element of _pathspec_pathspecs (documented: 'Everything after is pathspec data, including literal --help, -foo, or paths named --'), and git-shc appends that array verbatim to pinned_diff — so the candidate list can legitimately contain a literal '--' (hug shc HEAD -- -- foo.txt). The scan stops at it, preserving the documented escape hatch; git itself accepts pathspecs named like flags after '--' (probe-verified with a fixture file './-weird.txt', both single- and double-'--' stances pinned by a regression test).
**Alternatives**: Naive whole-list dash rejection: rejected — breaks the parse_pathspecs double-'--' passthrough and every valid call via the format slot. Whitelist-only rejection of known flags (--null/--no-renames) in non-leading slots: rejected — a generic dash-token check also catches typos (--patch, --name-onlyx) with the same coherent order-naming message and matches the issue acceptance wording. Reposition flags via getopt: rejected — pinned_diff is a thin plumbing layer with a deliberately hand-rolled leading-flag loop (e70a6ff); a parser swap is out of scope. Doing nothing at command level only: rejected — the guard belongs at the library boundary where all three call sites and future callers inherit it.
