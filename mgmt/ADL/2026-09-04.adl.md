## 07:28 — NUL-transport reader pattern for #285: temp file + read -d '' (house pattern), not mapfile -d ''

**Context**: elifarley/hug-scm#285: extract_files_from_commit had to switch from line-mode pinned_diff (git C-quotes structural-char filenames in every line mode — hug a --from-commit staged nonexistent C-quoted tokens) to pinned_diff --no-renames --null --name-only, and every consumer capture of that stdout needed a NUL-safe reader.
**Decision**: Added extract_files_from_commit_into <out_arr> <commit> in hug-file-input using the house NUL-transport pattern already established by build_scope_set in hug-pathspec: transport the -z stream through a mktemp FILE and read records with while IFS= read -r -d ''. All five consumers (git-a, git-us, git-untrack, git-ccp, lib collect_files_from_args) route through the one reader.
**Alternatives**: mapfile -t -d '' < <(extract_files_from_commit …): rejected — the process substitution detaches the subshell exit, but the rev-parse guard's failure must stay observable at the call site (git-us pins || exit $? — codex P2 regression test), and on main the SAME containment accident had made git-a answer exit 0 on an invalid commit. $(…) capture: impossible — bash variables cannot hold NUL bytes; command substitution strips them and concatenates every pathname into one record. mapfile -d '' from a plain redirect (no process substitution) would preserve neither the exit nor the uniform call shape.
**Sources**: https://www.gnu.org/software/bash/manual/bash.html#Command-Substitution, https://git-scm.com/docs/git-diff, https://git-scm.com/docs/git-diff-tree
**References**: elifarley/hug-scm#285

## 07:29 — Blast-radius verification method for the #285 mechanism change

**Context**: Issue #285 changes the mechanism action lists flow through (stdout contract of extract_files_from_commit flips line-mode to NUL records), so every consumer of that stream had to be inventoried and proven before any edit.
**Decision**: Three-layer method: (1) static — grep the whole repo for the function and its surrounding capture idioms (mapfile < <(…), $(…), mapfile <<<), yielding the 5-site inventory {git-a, git-us, git-untrack, git-ccp, collect_files_from_args} plus confirmation that --from-file/read_files_from_source are a different (user-authored, line-oriented) contract left untouched; (2) per-site failure-semantics read — each call site's error policy matched against its pre-change form (process substitution swallow vs $(…) || exit $?) before choosing the replacement; (3) dynamic — orchestrator-run od-level probes of pre/post behavior on a {back\slash.txt, plain.txt, we\nird} fixture, then independent per-consumer end-to-end probes (a/us/untrack/ccp) with byte-level index oracles (git diff --cached --name-only -z | cmp), so 'ordinary filenames byte-identical' is proven, not assumed.
**Alternatives**: Trusting the implementer's green test log alone: rejected — subagent output claims are treated as unverified until evidence-checked; the probes caught one real regression the implementer had mislabeled 'identical to pre-change behavior'.

## 07:29 — Guard-fatal contract for --from-commit consumers (spec-review fix round)

**Context**: Spec review caught that the #285 refactor changed invalid-commit behavior: production error() (hug-output) EXITS the process, so on main the mapfile < <(…) subshell had accidentally contained the guard failure — hug a --from-commit <bogus> answered 'No files to stage.' with exit 0, while the branch (reader in parent shell) exits 1. The implementer's || true swallow at git-a/untrack/ccp was dead code on the guard path.
**Decision**: Adopted guard-fatal site-wide: uniform || exit $? (|| return $? in the lib function), truthful doc comments, amended commit message, and a new unit pin (exit 1, error text, refute 'No files to stage.'). Rationale: the exit-0 swallow was an accident of process-substitution containment, never a documented contract, and it is the exact bug class the repo already fixed for hug us (codex P2: 'automation read a failed unstage as success'). Restoring byte-parity would have required hand-reconstructing error branding to preserve an accident — rejected as dishonest; git-untrack's exit code is unchanged (1, clearer message) and git-ccp's guard is unreachable (validate_commitish precedes extraction).
**Alternatives**: Option (b): restore the exact main-side swallow by pre-validating without error() — rejected: parity requires the guard error to fire inside a subshell, the design deliberately rejected subshells because the guard exit must survive (git-us codex P2), and hand-printing the ❌ branding duplicates error() to preserve an undocumented accident. Scope note: this is a deliberate contract change beyond #285's letter, documented in the commit message and PR body rather than smuggled in.
