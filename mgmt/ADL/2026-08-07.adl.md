## 06:56 — Implemented Codex P2 review finding (unborn-HEAD mislabel) rather than pushing back

**Context**: PR elifarley/hug-scm#252 review: the chatgpt-codex-connector bot left a P2 on validate_backward_target (hug-git-upstream:199) — on an unborn HEAD, commit_offset(target, HEAD) returns exit 3 because its SECOND arg fails, so the exit-3 arm conflated 'invalid target' with 'unborn HEAD' and mislabeled a valid saved SHA as 'not a valid commit'. This bites the real recovery flow: after reset_root_commit HEAD is unborn, and hug h restore <saved> --back routes the explicit target through this gate.
**Decision**: Implemented the fix (not pushback). The exit-3 arm now disambiguates with git rev-parse --verify for the target: if the target resolves, the failure is HEAD's (unborn) and the message says so + points at 'hug h restore <target> --<op>'; otherwise the existing 'not a valid commit' stands. Verified the bot's claim empirically before acting (reproduced the mislabel on a scratch unborn-HEAD repo), TDD'd the fix (new test asserts 'cannot resolve HEAD' + restore hint + refutes the mislabel; existing garbage test pins the unchanged invalid-target path).
**Alternatives**: Push back as out-of-scope (the batch's stated goal was garbage/forward rejection; unborn-HEAD recovery was not an explicit AC) — rejected: the bot was empirically correct, the fix was small and in the spirit of the batch's loud-failure/truthfulness theme, and the recovery flow is user-facing. Defer to a follow-up issue — rejected: cheaper to fold into the open PR than file+rebase later.
