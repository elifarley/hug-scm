## 06:36 — pathspec contract: select_files_with_status extension strategy

**Context**: PR elifarley/hug-scm#296 review (codex bot comment 3795205376): the plan told the executor to append pathspecs to select_files_with_status's 'internal list_files_with_status call', but the selector never calls that function — it invokes list_tracked/staged/unstaged/untracked/ignored_files directly at hug-select-files:690-755 (list_files_with_status is the separate non-interactive function at :312).
**Decision**: Forward the collected pathspecs at each of the selector's five existing list_*_files call sites (nullsafe appends) instead of refactoring the selector onto the shared list_files_with_status function. WHY: the selector's calls pass different flag sets than the shared function's, so consolidation is a behavior-changing refactor, not a simplification; the minimal five-site forward carries zero behavior risk and unblocks the scoped-picker feature. YAGNI: revisit consolidation if the :690-755 vs :387-465 duplication is ever unified.
**Alternatives**: refactor select_files_with_status to delegate to list_files_with_status (rejected: behavior-changing, larger diff, no user-visible gain)

## 21:15 — pathspec contract: picker-delegation semantics + separator-aware sinks (Codex round 2)

**Context**: Codex review round 2 on PR elifarley/hug-scm#296 (comments 3798420605/0610/0613/0617): four data/option-boundary defects — w-get `-u` order dependence, lc/lf/lcr picker delegation unioning pathspecs with the picked file, selector forwarding option-shaped pathspecs raw into list helpers, and batch JSON parsers consuming post-separator `--no-body` as flags.
**Decision**: One invariant applied at every sink, mirroring git's grammar: flags are recognized only BEFORE `--`; after it, tokens are data even when they spell a flag name. For the picker delegation specifically, the picked file REPLACES the user's pathspecs (git unions positive pathspecs, so appending would keep the whole scope and the selection would restrict nothing). Implemented via `--` arms in all five list helpers + `list_tracked_files` separator strip + separator-aware batch loops + order-independent `-u` extraction in w-get. Probing lesson: hug-git-kit resolves modules via HUG_LIB_DIR=$HUG_HOME/git-config/lib, so a bare `source lib/hug-git-files` probe silently tests the INSTALLED copy, not the worktree — set HUG_HOME or source the file by absolute path before trusting a probe.
**Alternatives**: reject unknown-shaped tokens loudly (rejected: post-`--` tokens are legal pathspecs by the contract this PR ships); consolidate batch parsers behind getopt (rejected for PR-A: PR-B already queues the picker-forwarding DRY extraction).
**Sources**: https://github.com/elifarley/hug-scm/pull/296, https://github.com/elifarley/hug-scm/issues/292, https://git-scm.com/docs/gitglossary#Documentation/gitglossary.txt-aidpathspec
