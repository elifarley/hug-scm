## 23:30 — Expose action-stance rename surface on hug shc CLI via --no-renames

**Context**: elifarley/hug-scm#283: v1.10.0 documented the pipeline 'hug shc -n -z main..HEAD | xargs -0 -r <cmd>' for action-list consumers, but it carries the DISPLAY rename stance (rename emits only the NEW path), so wiring it to rm/restore silently misses the OLD side — the same silent-shrink class rejected for 'hug a --from-commit'. The lib already pins both stances: pinned_diff [--null] [--no-renames] (hug-git-diff), but no CLI path reached --no-renames. Evidence probed on git 2.34.1: rename commit → 'hug shc -n -z HEAD' emits 'newname.txt\0' only, while pinned_diff --no-renames --name-only emits both sides.
**Decision**: Add '--no-renames' flag to 'hug shc', valid only with -n (stats mode or -n-less use → usage error exit 2 with a coupling message mirroring the -z guard). Thread through show_changed_file_names to the existing pinned_diff lib flag. Update the -z help bullet to state the display default and point destructive/action-list consumers at --no-renames; add an action-stance line to CAPTURING OUTPUT help; update docs/meta/hug-completion-reference.md shc entry and the docs/commands/head.md piping tip. Rationale: v1.10.0 established the two-valued rename contract at the lib level; exposing the action stance on the CLI completes it with the smallest surface, keeps the documented default pipeline backward-compatible (display stance unchanged), and makes the foot-gun discoverable at the exact place users read it — the -z help bullet.
**Alternatives**: Docs-only guidance (document the limitation and tell consumers to shell out to git diff-tree --no-renames themselves) — rejected: the help text's own documented pipeline IS the foot-gun; telling users to leave hug for the safe variant defeats hug's purpose and leaves the two-valued lib contract unreachable from the CLI. Alternative flag placement (e.g. a new -a/--action-stance mode flag) — rejected: --no-renames matches git's own vocabulary, threads 1:1 onto the existing lib flag, and avoids inventing a second name for one concept.
