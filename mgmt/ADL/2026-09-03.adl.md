## 22:48 — Consolidate list_/count_changed_files_in_range onto pinned_diff: DISPLAY stance, sort -u preserved (#282)

**Context**: Closing the last surviving raw git-diff call site of the class pinned_diff was created to canonicalize (elifarley/hug-scm#274 item 4). Completed the interrupted consumer audit: sole live caller of list_changed_files_in_range is git-config/bin/git-h-files:154 — a READ-ONLY preview (file count, emptiness message, --patch=FILE membership grep); count_changed_files_in_range has ZERO production callers repo-wide; sourcing chain verified (hug-common's _hug_common_libs loads hug-git-diff; hug-git-kit loads hug-git-repo -> hug-git-diff -> hug-git-commit in order), so pinned_diff is in scope at every consumer and in the existing test file with no new loads.
**Decision**: DISPLAY rename stance (pinned_diff's --find-renames default, NOT --no-renames): the only consumer is a preview, and pinned --find-renames equals git's default diff.renames=true, so default-config output stays byte-identical — pinned by a recorded-bytes regression test. The trailing '| sort -u' PRESERVED on top of pinned_diff (git's stream order is not a sorted contract; the sort upholds the documented sorted-unique contract; the -u dedupe is belt-and-braces for two-tree diffs) and made STRUCTURALLY load-bearing by a hostile diff.orderFile test — orderFile is deliberately unpinned by pinned_diff, and the 4-path HEAD~2..HEAD range is required because HEAD~1..HEAD is trivially single-path (correction caught in review: my original probe conflated the two because its scratch repo had only 2 commits). count_changed_files_in_range consolidated alongside despite zero production callers: same raw-invocation class in the same file, nil regression risk, keeps the pair from drifting apart again.
**Alternatives**: --no-renames ACTION stance: rejected — that contract exists for staging/untrack lists needing the deleted side; here it would break default-config byte-identity. Dropping sort -u as redundant: rejected — documented contract is sorted-unique, the acceptance requires byte-identity, and the orderFile test shows stream order genuinely diverges from sorted under hostile config. list_-only scope leaving count_ raw: rejected — same silent-divergence risk the issue exists to close.
